Your portfolio — the complete guide

Everything from scratch: running the website on your computer, editing it with the CMS, keeping backups, putting it on the internet with your own domain, and keeping it fast. No coding needed.

1 · Run it on your PC

One-time: Node.js

Node.js is the free engine that runs the website. Your PC already has it. On another computer:

  1. Go to nodejs.org and click the big LTS download button.
  2. Open the downloaded file and click Next until it finishes. Keep all the default options.

Start the website

  1. Open the portfolio folder (e.g. on your Desktop).
  2. Double-click START-WEBSITE. A black window opens.
    If a blue box says "Windows protected your PC": click More info → Run anyway. It shows this for any new file; it is safe.
  3. The first time only it downloads parts it needs — this needs internet and takes 2–5 minutes. Text scrolls by; that's normal.
  4. Your browser opens localhost:3000 with the 3D projects.
  5. Keep the black window open while you use the site (you can minimise it). It is the website running.

Stop it: close the black window.   Next time: double-click START-WEBSITE again — it starts in seconds and works without internet.

The first start should be done once while online so the fonts download too. After that, everything works offline.

2 · Use the CMS

Everything you save in the CMS shows up on the website immediately. Keep the website open in a second browser tab and press F5 to refresh it and see changes.

Log in (first time)

  1. In the portfolio folder, right-click .env.local → Open with → Notepad. (Not listed? Choose another app → Notepad.)
  2. Your email is after ADMIN_EMAIL= and your password is after ADMIN_PASSWORD=. Close Notepad without changing anything.
  3. With the website running, type localhost:3000/admin in your browser's address bar → Enter.
  4. Enter the email and password → Sign in.
  5. Change your password now: left menu → My account → type the old one, then a new one (10+ characters) twice → Update password. Write it down somewhere safe.
The password in .env.local is only used once, to create your account. After you change it in My account, the CMS uses your new one.

3 · Back up

All your content is in three things inside the portfolio folder:

  • .data folder — all text, projects and settings
  • storage folder — your uploaded pictures and videos
  • .env.local file — your login setup
  1. Close the black window first (copying while the website runs can give a broken copy).
  2. Select those three → right-click → Copy → paste onto a USB stick, Google Drive or OneDrive, in a folder named with today's date.

To restore: close the website, copy the three back into the portfolio folder (replace), start it again.

Once your site is online (part 4), the online version has its own content. Your PC copy then becomes your private test copy.

4 · Put it online with your own domain

Right now only you can see the site, on your PC. To let anyone visit yourname.com, the website has to run on a computer that's always on — a host. This guide uses Railway because it can run the whole thing (website + CMS + database + your uploads) with clicks only.

You needCost (approx.)
A GitHub account (stores your code online)Free
A Railway account, Hobby plan (runs the site)About $5 / month for a small portfolio
A domain name (e.g. from Cloudflare, Porkbun or Namecheap)About $10–15 / year
Prices and button names on these websites change from time to time. If a button is named slightly differently, look for the closest match — the steps stay the same.

A · Put your code on GitHub (once)

  1. Create a free account at github.com.
  2. Download and install GitHub Desktop (desktop.github.com) and sign in with that account.
  3. Close the website's black window. In GitHub Desktop: File → Add local repository → choose your portfolio folder. It says it's not a repository yet → click create a repository → Create repository.
  4. Click Publish repository (top). Keep Keep this code private ticked → Publish.
Your passwords (.env.local), database (.data) and uploads (storage) are never uploaded to GitHub — the project is set up to skip them.

B · Run it on Railway

  1. Go to railway.com → sign up with Login with GitHub. Choose the Hobby plan.
  2. New Project → Deploy from GitHub repo → pick your portfolio repository. (If asked, allow Railway to access it.) It starts building — it will fail or wait the first time; that's fine, we'll add settings next.
  3. Add a database: in the project, click + Create (or New) → Database → PostgreSQL.
  4. Add storage for uploads: right-click your website box (not the database) → Attach volume (or + Create → Volume and connect it to the website). Mount path: /data
  5. Settings (variables): click your website box → Variables → + New Variable, add each of these:
    NameValue
    DATABASE_URL${{Postgres.DATABASE_PUBLIC_URL}} — type it exactly; Railway fills in the real address
    UPLOAD_DIR/data/uploads
    ADMIN_EMAILyour real email
    ADMIN_NAMEThavanesh
    ADMIN_PASSWORDa new long password (12+ characters) — not the one from your PC
    SITE_URLfor now the Railway address (next step); later https://yourdomain.com
  6. Get a temporary address: website box → Settings → Networking → Generate Domain. You get something like portfolio-production.up.railway.app. Put it (with https://) into SITE_URL.
  7. Railway rebuilds automatically after variable changes (or click Deploy). The first build sets up the database by itself: it creates your admin account and copies in your 5 projects. Wait until it shows Active / Success (a few minutes).
  8. Open the Railway address: your 3D portfolio is online. Go to …/admin and sign in with the ADMIN_EMAIL and ADMIN_PASSWORD you just set.
Content online starts fresh (your 5 projects + settings). Things you changed or uploaded in the CMS on your PC are not copied automatically — make your final edits and uploads in the online CMS. From now on, treat the online CMS as the real one.

C · Connect your domain

  1. Buy a domain (if you haven't) at Cloudflare Registrar, Porkbun or Namecheap — e.g. thavanesh.com. Their search box shows what's free and the price.
  2. In Railway: website box → Settings → Networking → + Custom Domain → type your domain (e.g. thavanesh.com) → add. Do it again for www.thavanesh.com if you want both.
  3. Railway now shows DNS records to add (usually a CNAME with a value like xyz.up.railway.app, sometimes also a TXT record). Keep this page open.
  4. At your domain shop: open your domain → DNS (or Manage DNS) → Add record → copy each record exactly: Type, Name (Host) and Value (Target). For the bare domain the name is @.
    Namecheap and some others don't allow CNAME on @ — choose ALIAS (or ANAME) instead with the same value. Cloudflare handles it automatically.
  5. Wait. It usually works within 15–60 minutes (sometimes up to a day). Railway shows a green tick when it's connected, and adds the padlock (HTTPS) for free.
  6. Update the address everywhere: Railway SITE_URL → https://thavanesh.com, and in your online CMS: Settings & theme → Site → Public URL → same → Save. This makes Google and social media previews use your domain.

5 · Speed & file size

What visitors download

PartSize (compressed)When
Page HTML≈ 6 KBImmediately
Website code + styles≈ 186 KBImmediately
3D engine≈ 203 KBRight after the page appears (doesn't block it)
Project framessmall previews first, sharp versions afterProgressively
Videos, case-study imagesonly when scrolled into viewOn demand
CMS codenever, for visitorsOnly on /admin

Already built in

  • Pages are prepared in advance and served from cache; saving in the CMS refreshes only what changed.
  • Uploaded pictures → WebP (much smaller than JPG), max 2560 px, plus a tiny preview for the 3D frames.
  • Case-study pictures are resized per screen (phones get small files) and served as AVIF/WebP.
  • The 3D world stops drawing when a case study covers it, when the tab is hidden, and the liquid cursor effect switches off when the mouse is still.
  • Uploaded files are cached by browsers for a year; images in the project folder for a day.
  • Fonts: only the ones your theme uses are downloaded.

Your part: keep uploads sensible

  • Videos are the biggest risk. Keep loops short (5–20 s), no sound, 720p or 1080p, ideally under 15 MB. A free tool like HandBrake (preset "Fast 1080p30", or "Fast 720p30") shrinks them a lot.
  • Photos straight from a camera are fine — the CMS shrinks them — but screenshots are better saved as PNG/JPG at normal size.
  • Delete unused uploads in Media now and then.

The folder on your PC is big — why?

About 500 MB is node_modules (the downloaded parts) — that never goes online and isn't needed in backups. If you need space or want to send the project to someone: close the website, delete node_modules and .next, and the folder becomes about 20 MB. START-WEBSITE downloads the parts again next time (needs internet).

6 · Problems?

What you seeWhat to do
Browser: "can't reach this page"The website isn't running. Double-click START-WEBSITE, wait ~10 s, press F5.
Black window closes instantly / red errorsFirst run needs internet. Try again. If it persists, copy the window's text (select it, Enter copies) and send it to Claude.
"Port 3000 is in use"It's already running in another black window — use that one, or close it and start again.
Changes don't appearDid you click Save? Is the item Published (not Draft)? Refresh with F5.
"Database locked" messageTwo copies are running, or a backup copy is in progress. Close all black windows and start once.
Forgot CMS passwordAnother admin can reset it under Users. If you're the only admin, ask Claude for a reset command.
Railway build failedRailway → website box → Deployments → the failed one → View logs. Check the variables in step B5 are spelled exactly. Send the red lines to Claude if stuck.
Domain not working after a dayCompare the DNS records at your domain shop letter by letter with what Railway shows. Remove older records for the same name.

7 · Words explained

localhost"This computer". localhost:3000 is the website running on your own PC — only you can see it.
CMSContent management system — the /admin control panel.
Publish / DraftPublished = visible on the website. Draft = saved but hidden.
SlugThe project's part of the web address, e.g. /projects/gond. Changing it keeps the old address working.
DatabaseWhere all your text and settings are stored (the .data folder on your PC, PostgreSQL online).
HostA computer on the internet that runs your website all the time (here: Railway).
Domain / DNSYour web address, and the "phone book" settings that point it to your host.
GitHubOnline storage for code; Railway reads your code from there.
DeployRailway building and starting the newest version of your site.
